# 测试开发方案（L1 纯 C# 单测 · L3 三进程联测 · 四层金字塔）

> 制订日期：2026-09-08
> 前置：《M0实施指导》（各件自测清单、M0SelfTest）、《状态同步实施方案》（M7–M12 验收）。
> 一句话定位：**三个零依赖程序集（LiteFramework.Core / LiteSim.Core / LiteNet）可以完全脱离 Unity 测试——`dotnet test` 秒级反馈是主回路，Unity 测试是慢回路，headless 三进程联测是联机验收的自动化形态。** 这是 `noEngineReferences` 设计的第四次兑现。
> 覆盖判定：哪些能测、用什么测、什么时候接进来；同样重要的是**不自动化清单**（§7）。

## 1. 前置工程（L1 之前必须完成的三件）

### 1.1 Debug 宏统一（最实际的一堵墙）

**现状**：Core 代码用 `#if UNITY_EDITOR || DEVELOPMENT_BUILD`（ReferencePool / EventCenter / Log 等 ~10 处）——在 .NET xUnit 下这些宏未定义，**走 release 分支，Debug 校验（重复归还检测、池溢出检测等）全部不可测**。

**修法**：所有条件编译改为三宏并集——

```csharp
#if UNITY_EDITOR || DEVELOPMENT_BUILD || LITEFRAMEWORK_DEBUG
```

- Unity 侧行为不变（前两个宏照常生效），无需全局加 symbol
- 测试 csproj 的 `DefineConstants` 显式定义 `LITEFRAMEWORK_DEBUG` → Debug 校验在测试里全量激活
- 约 10 处替换 + 一次全量回归；**新代码禁用裸 `UNITY_EDITOR` 判 Debug 行为**（进 lint 清单）

### 1.2 双轨编译（asmdef + csproj）

三个零依赖程序集要在 Unity 与 dotnet 两个世界编译。每个配一个 **SDK-style 手写 csproj**（`net8.0`，放在程序集目录内）：

- SDK-style 默认 glob 目录下全部 `.cs`——**加新文件零维护**，这是双轨成本可控的关键
- `DefineConstants`：`LITEFRAMEWORK_DEBUG`
- 范围锁死三个程序集 + `Server`：**有引擎引用/第三方引用的一律不进双轨**（LiteSim.View / LiteGame 不建 csproj）
- `.csproj` 不进 Unity 编译（Unity 忽略它），加 `.gitignore` 不需要——保留入库供 dotnet 用

```
Tests/                          ← 与 Assets 平级，Unity 不编译
├─ LiteFramework.Core.Tests/
├─ LiteSim.Core.Tests/
├─ LiteNet.Tests/
├─ Server.Tests/
└─ Tests.sln                    ← dotnet test 一键
```

### 1.3 M0SelfTest 断言迁移（权威转移）

- **正式断言的唯一权威 = 测试项目**；`M0SelfTestRunner`（mono 组件）降级为"Play 模式冒烟"
- M0 指导各件的"自测"小节清单逐条翻译成 xUnit facts（事件中心零 GC、ReferencePool 容量/裁剪、FSM 切换语义、DI 解析时点报错 + Seal、设置件往返与钳制、时钟三域互不干扰……）
- 两处清单不一致时**以测试项目为准**——写进 M0 收尾对账（§14）

## 2. L1 单测规范

### 2.1 用例映射（已有清单 → 测试）

| 来源 | 用例 |
| --- | --- |
| M0 §3 事件中心 | 订阅/注销幂等、派发中改集、队列延迟、StrictMode、**零 GC 用例**（`GC.GetAllocatedBytesForCurrentThread` 前后差值为 0——.NET 有同款 API，直接迁移） |
| M0 §4 引用池 | 容量上限/裁剪/预热上调、重复归还抛、Debug 追踪 |
| M0 §6 FSM | 切换语义、重入抛、`GetData<T>` 类型不符抛、OnLeave 禁改道 |
| M0 §7 时钟 | 三域互不干扰（暂停/时停/墙钟）、ScaledDelta、timeline 跳帧安全 |
| M0 §10 DI | 解析时点报错（未注册 / 循环依赖含链 / 重复注册 / 构造抛真因）、Seal、注册即发现 |
| 状态同步 §2 | **IEEE 边界用例**：加乘除/sqrt 在 .NET 与 Unity 各跑一份**比对结果文件**（跨运行时）；`SimTrig` 查表精度；lint 抓 `Math.Sin` |
| 状态同步 §3 | 固定输入 3000 帧、槽位分配/版本号、checksum 按位哈希、命令缓冲分批、`EntityIt` 过滤 |
| 状态同步 §5 | SnapshotRing 深度/回退、InputHistory、回滚重放一致性 |
| LiteNet | **Protocol 打包/解包 roundtrip、冗余解包、丢包容错**——纯函数层，最好测 |
| Server | AuthSim Step、**SnapshotDiffer 性质测试：增量快照应用后 == 全量快照（不变式，值千金）**、Room 聚合定序 |

### 2.2 惯例

- **确定性是最好的 test double**：Sim/SimRng 注入种子直接用真物，不 mock；mock 只出现在 DI 服务边界（网络契约、配置服务）
- 时间断言不依赖 `Environment.TickCount` 精度（Log 的 Tick 字段不断言具体值）
- 命名：`{件名}_{行为}_{预期}`（如 `ReferencePool_Release_超过上限_丢弃并计数`）

## 3. L3 联测：headless 客户端（零依赖红利最大兑现）

### 3.1 形态

```
headless client = LiteNet + LiteSim.Core + 脚本输入序列（纯 C#，无 Unity）
```

因为 Sim 与 Net 零依赖，联机测试**不需要 Unity 参与**。两档：

| 档 | 形态 | 用途 |
| --- | --- | --- |
| **进程内** | 测试 fixture 直接 `new` Room/AuthSim/headless 客户端对象，loopback 互发 | 默认——快、稳定、可断言内部状态 |
| **真三进程** | Server 进程 + headless ×2 独立进程，真实 UDP 栈 | 合并前——验证真实 socket 路径 |

### 3.2 断言（即 M10 验收的自动化形态）

- 对跑 5 分钟：**和解率 < 阈值**（客户端上报汇总）、无状态发散
- 丢包注入 10%：不卡死、追帧不雪崩
- 注入不确定性（人为改一帧输入）→ 服务器对账标记触发
- SnapshotDiffer 不变式（每次广播断言：增量应用 == 全量）

**丢包注入点**：LiteNet 的 `Protocol/Transport` 分层（§4.6 两刀）天然支持——Transport 实现一个带丢弃率的包装即可，不碰 Protocol。

### 3.3 帧同步预案的四端用例（触发预案时）

.NET 侧与 Unity 侧各跑同一输入序列 → 各自导出 checksum 文件 → 比对。测试架构不变，跑的范围变（预案文档 §1 的 M7′ 验收）。

## 4. CI 骨架

```
PR / 每次提交：
  ① dotnet test Tests.sln                    （秒级，L1）
合并前 / 夜间：
  ② Unity batchmode -runTests -testPlatform EditMode   （L2）
  ③ dotnet test 三进程联测过滤用例            （L3）
发布前：
  ④ 真机包 + 手动 L4 清单
```

Unity 机器成本是 ② 的门槛——①③ 不需要 Unity，**日常开发只跑 ①**，②③ 挂夜间/合并。

## 6. 纪律与边界

1. **测试不证明"跨平台确定性"本身**——只证明测过的序列一致。float 版靠快照兜底无所谓；帧同步预案下（M7′）用例必须覆盖尽可能多的运算路径，且这是生命线级验收。
2. **不自动化清单**：Lua UI（§7.8 异常兜底 + 手动）、手感旋钮（inputDelay/插值缓冲——靠和解率观测指标 + 人）、纯表现（粒子/动画/转场）。
3. **权威转移**：M0SelfTest 与测试项目冲突时以测试项目为准；新代码的自测清单直接写进测试项目，不再扩 M0SelfTest。
4. **Lint 与测试互补**：lint 抓"禁用写法"（`Math.Sin`/裸 `UNITY_EDITOR`/Dictionary 遍历），测试抓"行为正确"——两者缺一不可，lint 不是测试的替代品。
5. **静态状态与测试并行**：Core 有三处全局可变静态（`Log` 环形缓冲 / `ReferencePool` 池字典 / `FileSys` Init 标志）——触碰它们的测试类必须 `[Collection("CoreStatic")]` 串行化，否则 xUnit 并行互踩。新测试类触碰静态状态时加 collection 是 PR 纪律。
