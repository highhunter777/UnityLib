# 框架流程说明手册

> 配套文档：《自研框架设计方案》（为什么这样设计）、《框架实施手册》（每一步怎么造出来）。
> 本文回答一个问题：**实现完成后，这套框架是怎么运转的。** 面向用框架写业务的日常视角。

---

## 一、全景：一层引擎，两层内容

| 层 | 装了什么 | 变更方式 |
| --- | --- | --- |
| 包内固定 | 自研轻量骨架（含游戏时钟/时序执行器）、DI 容器、Lua 逻辑注册表、薄壳（UI/实体/声音/场景）+ 通用组件、三座桥、Luban.Tables 生成代码、玩法系统、内容解释器 | 出包（版本节奏） |
| 热更 · 代码 | `Lua/` 全部：main、core、content、ui | YooAsset 下发（运营节奏） |
| 热更 · 数据 | Luban `.bytes`（含注册表三件套）、lua 表 | YooAsset 下发（运营节奏） |

```
C#（稳定层，出包才变）
  自研轻量骨架 ── DI（单例服务）
  玩法系统（战斗/Buff/技能/AI/任务引擎）      内容解释器（剧情/引导/活动）
  薄壳（UI/实体/声音/场景）+ 通用组件（虚拟列表/红点/转场）
        ▲ 三座桥（服务/事件/生命周期）          ▲
        │                                      │
Lua（内容驱动层，可热更）
  单界面逻辑表（UI.*）   内容脚本（剧情/引导/活动步骤）   core/（元表/闭包/协程工具）
```

一句话分工：**规则在 C#，内容在 Lua**；Lua 是可执行的内容层，不是第二门业务语言。

## 二、开发期工作流

### 2.1 导表流（策划视角）

1. 改 `Luban/Data/*.xlsx`（业务表；注册表三件套 TbUIForm / TbContentEntry / TbStrategy 也是普通表）
2. 跑 `Luban/gen.bat`，产物三路：
   - 强类型 C# 表代码 + `Bridge.data` 门面代码 → `Assets/GameData/Generated/`（编译进包）
   - binary `.bytes` → RawFile 配置目录（热更资产）
   - lua 表 → `Lua/cfg/`（热更资产，内容脚本可直读）
3. Unity 重编译，结构错误就地暴露

### 2.2 程序迭代流

- **改 C#**：出包层代码。Editor 重编译即见效果（框架/壳/解释器/玩法都是 C#）
- **改 Lua**：EditorSimulateMode 直读文件系统，改完执行**重载 LuaEnv**（菜单/快捷键）→ main.lua 重跑，秒级生效——学习与内容迭代的主循环
- **改表**：gen.bat → Editor 下重新加载配置即生效

### 2.3 例：新增一个"活动日历"界面，要动什么

| 步骤 | 产物类型 | 是否出包 |
| --- | --- | --- |
| 做 prefab + 绑定数据 | 资源 | 否（YooAsset） |
| 写 `ui/UIActivityCalendar.lua` | Lua 逻辑表 | 否 |
| TbUIForm 加一行（Id/Lua路径/Prefab/层级） | 表数据 | 否 |
| 需要新转场动画策略 / 新控件类型 | 壳机制 | **是**（罕见路径） |

结论：常规加界面 = 三件热更资产，零 C# 改动。这正是内容驱动层的核心收益。

## 三、启动时序（每次进游戏）

**阶段 0 · 引擎装配（各组件 Awake）**
- `GameEntry` 建根容器（**不静态暴露**，装配完成移交流程）；各组件 Awake 只做 `RegisterInstance`（薄壳、资源桥等）；薄壳实现 ITickable，交由 GameEntry 统一驱动（不用各自的 Update）
- 禁止 Resolve（Debug 断言）——此时容器里只有实例，没有依赖图构建

**阶段 1 · ProcedureLaunch（DI 装配）**
- 注册全部单例服务并完成解析（构造注入；循环依赖此步直接抛错）
- `IConfigService` 此时只拿到字节加载委托，尚不接触资源

**阶段 2 · ProcedurePreload（资源就绪，五步顺序不可换）**
1. YooAsset 初始化（Editor 模拟/离线直通；联机做版本检查 + 增量下载）
2. 全量预载 Lua 目录 → 建立"路径 → 字节"缓存（同步 loader 的硬前提）
3. 执行 `main.lua`：require/定义逻辑表（不注册任何东西）
4. 配置加载：`IConfigService.LoadAsync` → AssetService 读 `.bytes` → Tables 构建
5. **读表填充**：C# 读 TbUIForm/TbContentEntry/TbStrategy → 逐行 require、校验 Lua 路径、包适配器 → 填充 Lua 逻辑注册表
6. 全部通过 → 放行进 Main；任一失败 = 启动期报错，拒绝进入

**阶段 3 · ProcedureMain（Lua 接管）**
- 打开 UIMain：UI 壳查注册表 `Get("UIMain")` → 适配器 → 实例化 prefab → `self:OnInit/OnShow`
- 此后玩法规则由 C# 系统执行；内容、界面逻辑在 Lua

## 四、运行期典型流转

### 4.1 查表

```
Lua: Bridge.data.GetItem(1001)
  → 生成门面 → cfg.Tables.Tbitem.Get(1001)
  → 转 LuaTable（按行缓存，首查后零转换）→ 返回
```

高频场景（虚拟列表刷新）复用同一行缓存，没有重复转换。

### 4.2 打开界面

```
Lua: Bridge.ui.Show("UIBag", userData)
  → UI 壳：入栈 + 层级/Depth 分配（策略可被 Strategies 覆盖）
  → Lua 逻辑注册表 Get("UIBag") → IUIFormLogic 适配器（启动期已就绪）
  → AssetService 实例化 prefab → 适配器转发 → self:OnInit(...) / self:OnShow(userData)
```

- 关闭：壳出栈（出栈拦截策略可否决）→ OnPause/OnHide → 回收
- 多开语义：同一界面类型共享一份 Lua 逻辑表（per-type 行为），实例状态由壳持有并经 userData 传入（xLua LuaBehaviour 同款）

### 4.3 内容播放（剧情 / 引导 / 活动）

```
Lua 内容脚本 = 步骤表（文案 / 分支 / 等待）
C# 解释器   = 逐条执行步骤，经受控出口回调 Lua（选择分支、自定义条件）
```

- 脚本可用的指令面 = `Bridge.content` 白名单（正式清单见设计文档 §4.7，M5 排期前展开）
- 新指令类型 = C# 解释器加节点（出包）；内容组装永远在 Lua

### 4.4 事件

```
C# 玩法系统派发（如 MonsterHurt）→ 事件桥 → 逐回调 pcall → Lua events.on("MonsterHurt", fn)
```

- 单回调抛异常：Log.Error（带堆栈与标识）→ 派发链继续 → 其他监听者不受影响
- `events.on` 返回注销委托，注册/注销必须配对

### 4.5 策略覆盖

- 壳的策略点（层级 / 转场 / 出栈拦截）有 C# 默认实现
- TbStrategy 指向 `Strategies.<名>` 时，启动期用 Lua 实现覆盖
- 运行中策略不热切换：进 Main 后固定

### 4.6 场景切换

```
Procedure 决策切场景 → SceneService.Load/Unload（UniTask + 进度）→ 激活 → 框架事件通知
```

- 切换决策在流程（Procedure），加载/卸载机制在场景服务
- 业务禁止裸调 `AssetService.LoadSceneAsync`——场景操作统一经 SceneService
- 时序动作（技能/演出的时间轴）走 C# 时序动作执行器：游戏时钟驱动，支持暂停/时停/变速；动作序列数据进 Luban 表可热更调参；表现与判定分离（DOTween/Animator 只做表现，判定走执行器）

## 五、热更链路

| 改动 | 生效路径 | 出包？ |
| --- | --- | --- |
| 改 Lua（内容脚本/界面逻辑） | YooAsset 重打包 → 下发 | 否 |
| 改表内容 / 加界面 | Excel → gen.bat → 重打包 → 下发 | 否 |
| 表结构变更（加列） | 生成代码变化 | 是 |
| 壳机制 / 解释器节点 / 玩法规则 | C# | 是 |
| 自研骨架 / DI / 注册表 | C# | 是 |

线上流程：改内容 →（如表则跑 gen.bat）→ YooAsset 打包 → 上传 CDN → 玩家下次启动 Preload 检版本 → 增量下载 → 生效。

## 六、异常与边界行为

- **pcall 边界**：生命周期适配器每个入口、事件桥每个回调。其余不 pcall——填充期、启动校验的错误应当炸醒人，不该被吞
- **错误可见性**：所有 Lua 异常回传 C# `Log.Error`，带堆栈 + 界面/实体标识
- **恢复语义**：单界面异常 → 该界面失效但不炸壳；单回调异常 → 派发链继续；注册表校验失败 → 拒绝进入 Main
- **调试**：自写迷你开发 HUD（**Editor-only asmdef**，打包剥离）看 C# 内脏——FPS/内存走 Unity 原生，骨架各件 stats 实时数据；配置链路另配 `LiteGame/Config/Smoke Panel` 面板（表查询/产物核对/场景操作）；VSCode + LuaPanda 断 Lua（hook 仅 Editor 开，打包关闭）。两侧组合拳

## 七、日常红线速查

| 红线 | 一句话 |
| --- | --- |
| 资源唯一入口 | 一切加载走 AssetService，禁止 File/Resources 直读 |
| 白名单 | 业务 Lua 不出现 `CS.`；填充 API（ILuaRegistry）不导出 |
| 壳只做机制 | 策略一律接口化，Lua 经注册表覆盖；通用组件归壳，只留数据口子 |
| 规则不进 Lua | 战斗/Buff/AI/任务引擎改动在 C#，出包 |
| 异步契约 | 公开 API 用 UniTask + CancellationToken，禁止新增 Action 回调风格 |
| 异步收口 | UniTask 时间/调度原语不裸调：时间类走时序动作执行器，加载/配置走各服务 |
| 日志收口 | 统一走 Log 门面（分级 / 环形缓冲 / HUD 数据源），禁止散落 Debug.Log；Lua 侧经 log.* 白名单 |
| 持久化收口 | 本地文件读写统一走 FileSys（原子写内建 / JSON 快捷），禁止散落 System.IO.File；归档虚拟文件系统按需回补 |
| 单线程 | 事件、DI、Lua tick 全部主线程 |
