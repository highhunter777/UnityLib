
## 三、M1 Lua 逻辑注册表 + DI

**目标**：IServiceContainer + ILuaRegistry 两个模块可用并通过 demo 验收。

### 3.1 IServiceContainer（约 400 行，克制）

```csharp
public interface IServiceContainer {
    void Register<TInterface, TImpl>() where TImpl : TInterface;   // 仅单例
    void RegisterInstance<TInterface>(TInterface instance);
    T Resolve<T>();                                                // 最长构造反射，缓存单例
}
```

- 实现要点：`Dictionary<Type, …>`；Resolve 用解析栈检测循环依赖，**直接抛**（不做自动解）
- `GameEntry : MonoBehaviour` 在 Awake 创建并持有根容器（自研骨架没有模块管理器，DI 不挂靠任何模块系统；**容器不静态暴露**，装配完成移交 `ProcedureLaunch`——见设计方案 §3.3）
- **解析时序契约（无运行时开关）**：组件 Awake 只许 `RegisterInstance`、禁止 `Resolve`；一切解析发生在 ProcedureLaunch 装配之后。防线是未注册异常（解析时点当场抛）+ `Seal()` 封注册面 + 流程顺序契约，容器无 `AllowResolve` 之类的运行时开关（原 `Validate()` 全量预检已删，见《M1实施指导》§1）

### 3.2 ILuaRegistry

```csharp
public interface ILuaRegistry<T> {
    void Fill(string name, T impl);   // 仅 C# 读表后调用，不导出给 Lua
    T Get(string name);               // 未命中抛异常，报错信息带路径约定提示
    bool Has(string name);
}
```

- 实现 = `Dictionary<string, T>` + Fill 重复名断言；泛型按用途实例化（IUIFormLogic、内容入口等）
- 填充期/解析期为**流程顺序纪律**（ProcedurePreload 尾部填充、ProcedureMain 后解析）——原 Debug 断言机制（LuaRegistryTiming/AllowRefill）已于 2026-09-10 决策删除，见《M1实施指导》§1

**自测**：demo——注册测试服务与假适配器（此时还没有 Lua），**M0 骨架各件（事件中心/游戏时钟/FSM）由 GameEntry 创建后 RegisterInstance 进 DI——接线动作在此步认领**；验证 DI 注入、注册表 Get、循环依赖报错。

## 四、M2 配置链路

**目标**：Excel → 一键 gen.bat → C# 强类型查表 + RawFile 数据 + 注册表三件套就绪。

| # | 步骤 | 说明 |
| --- | --- | --- |
| 1 | 迁移 Luban 工具链 | 整目录拷 `E:\unityProject\Test\Luban`；生成器在 `LubanGenerater\Luban\Luban.exe`（4.11 已验证） |
| 2 | gen.bat 改双输出 | 第一遍 `-c cs-bin -d bin`（代码→Assets/GameData/Generated，数据→RawFile/Config）；第二遍 `-d lua`（→ LiteGame/Lua/cfg） |
| 3 | 建注册表三件套 | Data 下加三个 xlsx：TbUIForm（Id/Lua路径/Prefab/层级/全屏，路径必填）、TbContentEntry、TbStrategy（全可空）；进 `__tables__.xlsx` |
| 4 | 生成代码 asmdef | `GameData/Generated/Luban.Tables.asmdef` 只引 Luban.Runtime（试验工程已有同名可拷） |
| 5 | IConfigService | 见下骨架；走 AssetService，UniTask + CancellationToken |
| 6 | Bridge.data 门面生成器 | gen.bat 后置一步的小工具：读表清单按模板输出 `Bridge.Data.cs`，**按行缓存转换结果**；M2 期间可先手写两个门面方法验证链路，生成器在里程碑结束前补上 |
| 7 | link.xml | `Luban.Runtime`、`Luban.Tables`、`LiteFramework` preserve="all" |
| 8 | SceneService 薄壳 | 封装 YooAsset 场景加载/卸载/激活与进度（UniTask 签名，DI 单例）；切换决策归 Procedure，**业务禁止裸调 `AssetService.LoadSceneAsync`** |

```csharp
public interface IConfigService {
    Tables Tables { get; }
    bool Loaded { get; }
    UniTask LoadAsync(CancellationToken ct);   // AssetService.LoadRawFileBytesAsync → ByteBuf → new Tables(file => …)
}
```

**自测**：gen.bat 跑通三路产物；C# 侧 `Tables.Tbitem.Get(1001)` 取到试验表数据；注册表三件套生成的 Tables 类可枚举行数；故意删掉一个 .bytes → LoadAsync 报错明确。

**坑**：RawFile location 用资源完整路径；Android 下 StreamingAssets 不可 File 读——一开始就统一走 AssetService，别留 File.ReadAllBytes 分支。

## 五、M3 xLua 集成

**目标**：Lua 跑起来、能调试、秒级迭代、注册表从真实表填充。

| # | 步骤 | 说明 |
| --- | --- | --- |
| 1 | xLua 导入 + 导出配置 | **xLua 源码 asmdef 化**：`Assets/XLua/Src` 建 xLua.asmdef，**名字必须避开 `xLua`**——工程自带各平台原生插件 `xlua.dll`（Plugins/WSA 等），同名会触发 Unity "same filename as Assembly Definition" 错误，社区标准名 **`xLuaMain`**（试验工程已用此名；Src/Editor 靠 Editor 文件夹规则自动分离，Examples/Tutorial 留在 Assembly-CSharp 自动引用），否则 asmdef 化的业务程序集引用不到 LuaEnv——预定义程序集只能被引不能引人。自建 GenConfig，白名单**仅 `LiteGame.Bridge.*`**——Luban.Tables 不进白名单（Bridge.data 内部转 LuaTable，Lua 不触碰 Luban 类型），业务类型更不进；Generate Code；加 `HIDE_REFLECTION` 宏移除反射 fallback（以当前 xLua 版本文档为准） |
| 2 | LuaComponent | ① LuaEnv + 自定义 loader（同步签名，只从启动缓存取，未命中=校验漏项直接抛）② tick 派发（可开关）③ 执行 main.lua ④ Shutdown 清理 + Dispose |
| 3 | 预载清单 | Preload 内：按 YooAsset 资源清单枚举 Lua 目录 → 全量 LoadRawFileBytesAsync → Dictionary<string,byte[]>（API 以 YooAsset 3.0.x 为准） |
| 4 | 启动接线 | ProcedurePreload 内按序：初始化/热更 → 预载 Lua → main.lua → IConfigService.LoadAsync → 读三件套逐行 require/校验/包适配器 → Fill 注册表 → 放行 |
| 5 | 服务桥 | 启动时把 `Bridge.data/ui/content` 绑定成 Lua 全局表；**只导出这三个门面**，ILuaRegistry/玩法系统一律不导出 |
| 6 | 事件桥 | C# 事件 → 逐回调 pcall → Lua 回调表；`events.on` 返回注销委托 |
| 7 | Editor 迭代 | 确认 EditorSimulateMode；加菜单 `[MenuItem("LiteGame/Lua/Reload Env %&r")]`：Dispose 重建 + 重跑 main.lua |
| 8 | 迷你开发 HUD（开发期） | FPS/内存走 Unity 原生（Stats + Profiler 窗口）；骨架各件已暴露只读 stats，自绘几十行 IMGUI 面板读取；**最近 32 条日志 + 错误计数读 Log 门面环形缓冲**；asmdef: `LiteGame.DevHUD`（全平台编译 + 三宏 `#if` 剥离；**场景不挂组件，DevHUDBoot 在 AfterSceneLoad 自创建**——Editor-only asmdef 实测会剥离 play 模式场景组件，2026-09-10 修正）。自测：HUD 能看到对象池/FSM/事件实时数据与滚动日志 |
| 9 | LuaPanda | LuaPanda.lua 随 Lua 目录分发（EditorSimulateMode 下本地直读）；仅 UNITY_EDITOR 下 `require("LuaPanda").start()`（hook 仅 Editor 开，打包宏隔离）；VSCode 装 LuaPanda 插件 + attach 启动配置。自测：断点命中 main.lua |

**自测**（对应设计文档 M3 验收）：嵌套 require 链可用；Lua 调 Bridge.data 查表成功；注册表某行 Lua 路径不存在 → 启动期报错；改 .lua → Ctrl+Alt+R 秒级生效；VSCode 断点命中 Lua 代码。

**坑**：loader 是同步签名，任何"运行时再异步加载"的念头都是错的——一切靠启动期预载；LuaPanda hook 忘了打包隔离 = 真机莫名掉帧。

## 六、M4 薄壳三件

**目标**：UI/实体/声音壳 + Lua 适配器 + 绑定面 + 通用组件数据口子。

| # | 步骤 | 说明 |
| --- | --- | --- |

| 5 | 通用组件口子 | 虚拟列表数据源接口（Lua 侧实现，经适配器）、红点规则注册、转场策略注入 |

| 7 | 时序执行：调度器 + 序列执行 | 时钟语义之上：①调度器——动作点/定时注册、到期触发、可取消；②序列执行器——有序步骤表推进（剧情与技能共用）；M5 前就绪，三设计决策在此定死并记录 |

**坑**：策略别写死进壳（M3 之后必被挑战）；Lua 回调注册必须拿注销委托，UI 隐藏时注销（§7.3 内存红线）。

## 七、M5 纵向切片

> **实施顺序调整（2026-09-14 用户定案：先联机）**：本手册按序交付到 M4 收官后，顺序调整为**联机线优先**——《状态同步实施方案》§9 的 M7（数值）→ M8（Sim）→ M9（快照/回滚）→ M10（网络，含 protobuf/AOI/双策略装配点）→ M11（表现 + 联机 demo）→ M12（工具）**先实施**；本节 M5 与 §八 M6 **后置**（联机 demo 跑通之后）。
> **理由**：联机地基（Sim/网络）是最大不确定性，尽早暴露；M5 的消费者（剧情/引导/单机技能形态）不阻塞联机。
> **风险与缓解**：框架全链在联机前缺少一次单机纵向验证——缓解 = M11 demo 本身消费 UI 壳/控件库/表现层/时序（覆盖大部分链路），剧情/引导/单机玩法留待 M5′。
> **编号不变、只改顺序**（M7-M12 的既有文档引用全部有效）。

**目标**：主菜单 → 进场景 → C# 战斗刷怪 → Lua 剧情与引导穿插 → UI 结算。

| # | 步骤 | 说明 |
| --- | --- | --- |
| 1 | C# 战斗 | 刷怪/伤害/Buff 规则全在 C# 玩法系统；对象池复用实体 |
| 2 | 剧情解释器 | 步骤表驱动 + 等待模型（回调或协程二选一，定死）；节点：对话/立绘/选择/等待/镜头/任务查询 |
| 3 | 协议面清单落地 | 把设计文档 §4.7 展开成 `Bridge.content` 正式 API 清单并实现 |
| 4 | Lua 内容接入 | content/ 下写一段完整剧情 + 引导，穿插战斗触发 |
| 5 | Profiler 作业 | Unity Profiler 录列表刷新 + 高频事件，实测"动态转换 vs 生成代码静态桥"的耗时/GC 差距，记进本文档 |
| 6 | 时序执行落地 | 消费 M4 的调度器/序列执行器：技能与剧情的动作序列数据进 Luban 表（可热更调参）；**业务禁止裸调 UniTask 时间原语**，时间维异步统一走执行器；表现与判定分离（DOTween/Animator 只做表现，判定走执行器） |

**自测**：全流程无 `CS.` 裸引用、无 Resources.Load、无框架外 hack；改一段剧情文案 → 免包生效；时序执行器在 Timescale=0 与游戏逻辑暂停下仍正确冻结/恢复，动画表现与判定分离（表现走 DOTween/Animator，判定走执行器）。

## 九、贯穿性配置与横切小工具（建好一次，长期维护）

### 9.0 横切小工具（M0–M3 先行提炼，不等第二个消费者）

六项的共同特征：它们的多个消费者在设计里就已白纸黑字，因此随骨架期**先行提炼**，不玩"出现再抽"。

| 工具 | 形态 | 消费者 | 预算 | 落地时机 |
| --- | --- | --- | --- | --- |
| **SubscriptionBag** | `Add(注销委托)` 收集 + `Dispose()` 一把注销 | 事件中心、事件桥、绑定面、UI 壳、生命周期适配器 | ~40 行 | M0（随事件中心） |
| **SafeCall** | LuaTable 安全调用：捕获 + Log.Error（带堆栈与 tag 标识）统一格式 | 生命周期适配器、事件桥、Bridge.data/content 门面 | ~50 行 | M3（随事件桥首日） |
| **ITickable** | `Tick(realDelta)` 单参数接口 + GameEntry 按装配顺序驱动 | 游戏时钟、FSM、未来调度器 | ~20 行 | M0（随装配） |
| **UniTask 适配扩展** | `handle.ToUniTask<T>()` 等扩展方法族（YooAsset 回调 → UniTask） | AssetService、SceneService、IConfigService | ~40 行 | M2（随 AssetService 移植） |
| **IModuleStats** | `Name + Snapshot(Dictionary into)` 键值快照（调用方复用容器，实现 Clear 后填入）+ GameEntry 收集 | 开发 HUD（M3，消费端参考实现见 M0 指导 §12.5） | ~60 行 | M0（随装配） |
| **DevReload.All()** | 重载编排：清 Bridge 缓存 → 重填注册表 → 重建 LuaEnv → 重跑 main.lua（填充期断言机制已删——重填只需保证流程时序正确，无豁免标志可置） | Editor 菜单（M3 秒级迭代） | ~30 行 | M3（Editor-only asmdef） |

合计约 240 行。**纪律**：这六项的 API 面同样对账本表——"先行提炼"不等于"先写大"。
