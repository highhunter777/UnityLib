# 动作系统与特效服务设计

> 定案 2026-09-14（用户拍板两处边界）：
> ①**技能系统 → 动作系统**：覆盖**只盖"离散时序动作"**——技能 / 冲刺 / 蓄力 / 交互读条 / 死亡复活（受击硬直可选）；**移动 / 瞄准 / 连发射击不进**，仅以"**占槽互斥**"接入仲裁。
> ②**特效 = 服务（机制）+ 内容表**，不做"系统"；预算只做**基础预算**（同屏上限 + 低端机降级），跨特效的优先级/互斥**留位不建**。
> 关系：取代《自研框架设计方案》§8.2 的"技能系统"行与"VFX 服务"行的表述细节（**定位不变处保留原判据**）；数据链路上承《编辑器设计规划》§3（时间轴编辑器）、下接《联机Demo设计》§5。

## 1. 动作系统（ActionSystem）

### 1.1 为什么不是"技能系统"——四条并行路径的收口

现设计里"有时序的动作"散落四处：**技能**（表 + 前摇/判定，§8.2）、**普攻射击**（Input 开火 + 射速表 clamp）、**受击/死亡**（View 观察状态变化触发）、**交互**（未来读条）。四项各自长规则 = 中断/互斥/时序四套。

而**时间轴编辑器早已是动作级的**（判定轨/表现轨/动画轨/属性轨/事件轨，2026-09-14 定案）——数据层就是"一段动作的编排"，只是名字还叫技能。**M8 未开工，改名与泛化此刻成本最低。**

### 1.2 范围边界（进 / 不进）

| 进（离散、有时序、有前摇/持续/后摇） | 不进（连续状态） |
| --- | --- |
| 技能（`category = skill`）、冲刺（`dash`）、蓄力、**交互读条**（`interact`）、死亡/复活（`death`/`respawn`）、受击硬直（`hit`，**可选**） | 移动、瞄准、**连发射击**——由各自 System 每帧处理，是"状态"不是"动作" |

**理由（射击不进的正面陈述）**：连发是 60Hz 高频输入流，与"一次动作释放"的时序语义冲突；强行统一会让 Sim 结构变重且"动作"概念过载。但保留一条互斥接口（§1.4），避免冲刺 + 开火同帧乱套。

**明确不做**：行为树 / 节点图（技能编辑器已否决节点图，同理）；万能动作框架（"每实体一帧只推进一个动作"这条线钉死范围）。

### 1.3 数据与 Sim 结构

```
tb_action        动作时序（时间轴串：判定轨/表现轨/动画轨/属性轨/事件轨）＋ category ＋ 中断规则
tb_action_num    动作数值（冷却/前摇/伤害系数/半径/消耗…；策划面，可 diff 可热更）
```

- **Sim 内**（判定住 Sim，见《状态同步实施方案》§3.9 映射）：`ActionState { actionId, frame, phase }`——每实体一个定长小结构（快照增量极小），判定事件按**整数帧**触发
- **表现侧**：表现轨/动画轨/属性轨经时间轴导出数据消费（View 侧）；`silenceUntilFrame` 防重播仍在 View（§2.5）
- **与 Buff / 属性系统**：Buff **不是动作**（挂载/叠加/tick 另立）；Buff 与属性通过属性系统**改动作参数**（如加速影响冲刺距离），不反向依赖动作系统

### 1.4 中断与占槽互斥（本设计的核心机制）

| 规则 | 形态 |
| --- | --- |
| **单主动作槽** | 一个实体同一时刻只有一个主动作（否则冲刺 + 技能同帧乱套） |
| **中断规则表驱动** | `canBeInterruptedBy`（如：冲刺可被受击打断、技能施法中不可被打断、交互读条移动即取消） |
| **占槽仲裁接口** | 非动作系统（如射击）声明"我占用动作槽"→ `ActionSlots.TryOccupy(entity, tag)` / `Release(entity, tag)`；仲裁在动作系统内统一（**射击系统不认识动作数据**，只报占用） |
| **同帧多次请求** | 优先级 + 先来先服务（表里 `priority`），结果确定性（同输入同结果） |

### 1.5 表名与命名迁移（影响面）

| 旧 | 新 | 说明 |
| --- | --- | --- |
| 技能系统 / `tb_action_num` | **动作系统 / `tb_action_num`** | 《联机Demo设计》§5、《编辑器设计规划》§3 的表名同步改 |
| 技能表（时间轴） | **`tb_action`** | 时间轴编辑器导出目标（时序列 + 分类列） |
| "技能编辑器" | **"时间轴编辑器"** | 已于 2026-09-14 改名（沿用） |
| 技能 = 一个内容类型 | **技能 = `category` 的一个取值** | 注册表/表清单里的"技能"字样保留在内容语义处（如技能栏 UI），系统层不再用"技能"命名 |

### 1.6 验收

1. 表驱动跑通三类动作：`skill`（AOE）+ `dash`（冲刺）+ `interact`（读条），均能**中断/取消**符合表规则
2. 占槽互斥生效：开火中请求冲刺被依据规则拒绝（或打断，按表），**同输入帧结果两端一致**（联机确定性）
3. `ActionState` 进快照：增量大小符合预算，回滚重放后动作进度一致
4. 表现与判定同轴对齐（时间轴单源），无"判定 12 帧、表现 18 帧"错位

## 2. 特效：服务（机制）+ 内容表

### 2.1 定位判据（逐条对齐《设计方案》§8.1 四模式）

| 问题 | 判定 |
| --- | --- |
| 有玩法状态吗？ | ❌ 没有——不参与判定、不改 Sim（《动效设计方案》§0 原则 1"动效永不携带判定"）→ **模式三·表现服务** |
| 表 + 时长/挂点/缩放 + 预算 = 系统特征？ | ❌ 表是 Luban **内容**，预算是**壳内策略**，均不构成玩法状态 |
| 谁决定"何时播什么"？ | **只有一个真相**：联机下由 **View 观察状态变化**触发（《状态同步实施方案》§520）+ **时间轴表现轨**（非对局/动作编排）。做成"系统"（自带触发规则）会与动作系统表现轨**争夺真相** → 两处规则迟早分叉 |

### 2.2 API 草案（无状态、可并行调用、不认实体语义）

```csharp
public interface IVFXService
{
    VfxHandle Play(string name, Transform attach, bool follow, float scale = 1f);  // 表查地址 → 加载 → 播放
    void Stop(VfxHandle handle);
    void StopAll(Transform attach);        // 宿主回收时清挂载特效（"谁挂谁清"契约的执行点）
}
```

内部：YooAsset 异步加载（句柄池）→ prefab 池化 → 挂点跟随 → 时长/粒子结束自动回收 → `IModuleStats`（活跃数/预算，HUD 可见）。

### 2.3 三条边界（防职责混乱）

1. **UI 动效不并入**——走已交付的 `UiFx` 原语（DOTween 唯一出口）+ 时间轴属性轨；服务只管**世界粒子/prefab 特效**
2. **音效不并入**——声音壳（M4b 已交付）独立；**服务不调用其他服务**，由编排方（表现轨/观察层）分别调 VFX 与声音壳
3. **防重播住 View**——`silenceUntilFrame` 属观察层逻辑，不在服务内

### 2.4 基础预算与降级（本次定案范围）

- **同屏上限**：活跃特效数上限（`maxActive`），超出按"最旧先回收"（或拒绝播放 + 记日志，二者由配置选）
- **低端机降级**：画质档位（`GameSettings.Quality`）映射到"特效密度/粒子数上限"（策略在服务内，旋钮走设置）
- **留位不建**：跨特效的**优先级/抢占/同槽位互斥替换**——出现真实需求时加一个**薄策略件**在服务旁（仍不住玩法状态）

### 2.5 何时升级为"服务 + 策略件"

触发判据（任一命中）：①同槽位需要互斥替换（如武器不同元素特效只能存在一个）②需要按优先级抢占预算（战斗特效挤掉环境特效）③需要随实体状态自动切换（血量低 → 持续冒烟）。届时加 `VfxPolicy`（DI 单例，输入/输出皆纯数据），**服务本体不动**。

### 2.6 验收

1. 服务 API 跑通：播放/跟随/停止/宿主回收清理（挂载特效随宿主回收清零，符合"谁挂谁清"契约）
2. 基础预算生效：超上限行为符合配置；画质档切换改变粒子预算（Profiler 实测记录）
3. 池化生效：同 prefab 重复播放无新增实例（活跃数/池命中率入 `IModuleStats`）
4. 联机：特效由观察触发，回滚期间不重播（`silenceUntilFrame` 用例）
