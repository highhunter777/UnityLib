## 0. 与状态同步主路线的差异总览

| 维度 | 状态同步（主路线） | **帧同步（本预案）** |
| --- | --- | --- |
| 权威 | 服务器（广播状态快照） | **无**——各端跑同一模拟，靠确定性对齐 |
| 广播内容 | 增量状态快照（30Hz） | **只有输入**（60Hz） |
| 客户端模拟 | 预测（本地重放） | **全量模拟**（权威在端上） |
| 数值 | float + IEEE 边界 | **Q16.16 定点数**（§1，跨平台逐位一致的唯一保障） |
| 和解/回滚 | 重放本地输入 | **重放全体输入**（回滚深度 8） |
| checksum | 本地调试用 | **对账核心**（不一致 = 不同步事故） |
| 服务器 | 权威 Sim + SnapshotDiffer | **影子 Sim**（跑同一 Sim 记账：结算/对账/复查/重连） |
| 业界对标 | 荒野乱斗 / LoL / OW | 王者荣耀 / 星际魔兽系 / GGPO |

## 1. 数值层：定点数全套（M7′ 的内容，预案启动的第一件事）

> **为什么必须是定点数**：帧同步没有权威快照兜底，各端必须**逐位一致**——跨 Mono/IL2CPP/ARM64/x64，`float` 的超越函数（native libm）与编译器优化（FMA 融合、向量化重排）不保证一致，确定性长尾无法关闭。Q16.16 定点数（`long` 整数运算）是唯一彻底解。**从 float 切回定点数 = Sim 数值层重写**，这是预案已记账的成本（M7′）。

- **格式 Q16.16 / `long` 承载 / 单位米**：范围 ±32767 m，精度 15 μm。Unity 无 `System.Int128`，乘除需手写 64×64→128 位中间量（约 30 行）。禁止"先右移再乘"的偷懒写法——精度随输入量级变化，会埋下"只在特定速度下不同步"的幽灵 bug。Debug 下做溢出检测。
- **`Sin`/`Cos`/`Atan2` 走查表 + 牛顿迭代，表必须硬编码为常量**（Editor 菜单生成 `FpMathTables.cs`，生成物入库）。**严禁运行期用 `Math.Sin` 填表**——跨平台 libm 不一致是最隐蔽的不同步源。`Sqrt` 走查表初值 + 固定轮次牛顿迭代。
- **`SimRng`**：Xorshift64*，种子由服务器开局下发，随机状态进快照与 checksum。
- **确定性容器与遍历**：禁 `Dictionary` 遍历、禁不稳定 `Sort`、禁 LINQ、禁闭包分配、禁多线程——帧同步下这是**生命线**（快照覆盖兜底不存在）。
- **checksum 序列化**：定点数按 `Raw`（long）参与哈希。

**M7′ 重写清单**：`SimVector3`（float×3 → Fp×3）、`SimTrig`（float 查表 → Fp 查表）、SimWorldState 字段类型、所有 System 的运算点、SimConfig 常量（`dt = 1/60` 的定点表示）。约 1–2 周，验收 = v2 版标准：四端（Editor / Win Mono / Win IL2CPP / Android）跑同一序列 checksum 逐帧一致——**在帧同步形态下这从"质量指标"升回"生命线"**。

## 2. 网络层差异：输入中继（替换主文档 §4.3–4.5）

### 2.1 拓扑

```
Client ──Input(frameNo) [Unreliable+冗余]──▶ RoomServer ──FrameData(frameNo, allInputs) [Unreliable+冗余]──▶ 全体
        ◀──StartGame(seed, players, config) [Reliable]──┘
```

**网络只搬输入与帧号，不搬状态。** 服务器跑影子 Sim（记账员）但不广播状态——客户端各自跑完整模拟做表现，靠"同输入 + 同模拟 = 同状态"对齐。

### 2.2 影子 Sim 服务器（替换主文档 §4.5）

```
RoomServer
├─ Acceptor / SessionManager / RoomManager   （同主文档）
│   └─ Room
│       ├─ FrameAggregator   60Hz 定时：聚合本帧已收输入 → 缺席玩家记空/沿用 → FrameData 广播
│       ├─ ShadowSim         引用 LiteSim.Core：同帧率 Step，权威 checksum 与结算
│       ├─ ChecksumLedger    客户端上报 checksum vs 影子值对账；不一致 → 标记累计 + 存证
│       └─ InputHistory      输入环形历史——复查重放 + 重连补发
├─ MatchMaker / Ops          （同主文档）
```

**关键机制**：

1. **帧聚合是"尽力广播"，不是"等待 lockstep"**——到点就发，迟到输入进下一帧。等待式会把一个人的卡顿扩散给全房。
2. **掉线不停帧**——掉线者输入记空/沿用；重连 = 下发 InputHistory → 从帧 0 快进重放（帧同步下没有权威快照可发，这是唯一路径）。
3. **影子 Sim 与客户端同帧率 Step**：结算以影子结果为准；checksum 对账**不立即踢**——输入迟到/CPU 抖动都可能造成瞬时差异，标记累计超阈值转复查。
4. **版本一致性**：`Join` 时 buildHash 比对，不符拒绝进房——**帧同步下这是绝对红线**（版本差一位 = 必然发散）。

**能力边界**：影子 Sim 只能抓"与确定性结果不符"的作弊，抓不住"合法输入的自动化"（脚本走位）。

### 2.3 协议面（双通道同主文档 §4.2）

| 方向 | 包 | 通道 |
| --- | --- | --- |
| C→S | `Join(roomId, token, buildHash)` | Reliable |
| C→S | `Input(frameNo, wire, ack)` | Unreliable+冗余 |
| C→S | `ChecksumReport(frameNo, checksum)`（release 每 10 帧） | Unreliable |
| S→C | `JoinAck` / `StartGame(seed, configHash)` | Reliable |
| S→C | `FrameData(frameNo, allInputs[])` | Unreliable+冗余 |
| 双向 | 心跳 / `Leave` / `ReconnectReq/Resp(history)` | Reliable |

带宽优势是帧同步的主场：8 人房下行约 **11 KB/s**（状态同步 30Hz 增量快照约为其数倍）。

## 3. 回滚差异：重放范围 = 全体输入（差异于主文档 §5）

- 模型即 GGPO：本地立即用**预测输入**推进（远端 = 沿用上一帧），收到真实输入发现不符 → 回滚到分歧前一帧快照 → 用**全体玩家的真实输入**重放到当前帧。
- `inputDelay = 1`、`MaxCatchUp = 5`、`MaxRollbackFrames = 8` 三旋钮同主文档；超出回滚深度强制等待（正确性优先）。
- **开火等离散输入不预测**——预测一发凭空的子弹，回滚后玩家能看见（帧同步下此约束比状态同步更硬，因为预测命中会进回滚重放）。
- **View 重对齐（`silenceUntilFrame`）**：回滚重放期间特效静默，机制同主文档 §6.2，触发更频繁（全员回滚）——手感调参的主战场。
- checksum 对账回归核心位：不一致即①`Log.Error` 带帧号 ②dump 输入日志 ③暂停 Sim。**漏字段仍由 §3.1 固定布局的结构同源性杜绝。**

## 5. 风险红线（帧同步特有，启动预案时生效）

1. **跨平台确定性是生命线**——四端 checksum 用例不过 = 预案不可启动；这是本预案与状态同步的本质区别（状态同步靠快照兜底，帧同步没有任何兜底）。
2. **回滚深度与追帧上限是硬约束**——防雪崩；假死比卡顿更糟。
3. **`inputDelay`/`MaxRollbackFrames` 改动必须重跑全部一致性用例**。
4. **数值层重写（M7′）期间冻结玩法新功能**——float 与 Fp 两套并存期是 bug 温床，重写要一次到位。
5. **版本一致性检查从"建议"升为"绝对红线"**——buildHash 不符拒绝进房，无任何豁免。
