# M10 实施指导：网络层（状态同步 · kcp2k 双通道 · 服务器权威）

> 依据：《状态同步实施方案》**§4.1–4.6**（传输选型 / 双通道 / 拓扑 / 定帧追帧 / RoomServer 结构与协议矩阵 / 服务器选型与可替换性）、**§3.2**（定帧公式与带宽估算）、**§3.4.1**（命中延迟补偿 = 服务器回溯）、**§5.6**（重连——M11 编排，M10 交付服务器能力）、**§7**（INetworkService 契约与三点接法）、**§8.3**（BattleContext 生命周期）、**§9 M10 行**（验收定义）、**§10 红线**（1/3/4/6/7/9/11）、**§11-2/6/7**（开工检查）；《服务端架构设计》**§10**（战斗服收口 + **E1 背压降级 / E3 抗放大——"M10 起带"**、§10.1/10.2 MVP 不拆分 / 单循环）。
> 前置：**M9 已交付**（`SnapshotRing` 容量参数化 / `RollbackSim` 预测回滚 / `InputHistory` / 同运行时结论——服务器 .NET 权威重放自洽）；M8 收口批实测结论（Mono FMA 1-ULP 跨运行时底噪）作为和解率预期基线。

| 7 | **增量快照**：`SnapshotDiffer` 对比上一广播帧副本提取变化槽位（protobuf `SlotDelta`：zigzag + 量化整型），**带 frameNo + 全量 checksum + ackInput**；全量兜底：客户端 ack 落后 >N 帧或每 60 帧定期发全量。30Hz 起步（`SimConfig.SnapshotHz` 旋钮） | §4.5-7；checksum 供客户端和解判定（4 B 成本） |
| 8 | **命中延迟补偿 = 服务器回溯**：客户端 `Input` 包带 `viewFrame`（= ackSnapshot 推导，§3.4.1）；服务器收到开火输入 → `SnapshotRing(LagCompHistory=16).TryRestore(viewFrame)` → 在历史态上执行 `ShootingSystem.Run`（单系统执行，不推进 Frame）→ 恢复当前态。**不改 SimStep 顺序**——回溯判定是服务器单侧动作，不触 Sim 纯函数红线；`LagCompHistory=0` 关闭退路保留 | §3.4.1；M9 环复用；客户端不预判补偿结果（开火本就不预测） |
| 9 | **客户端预测形态 = 全量预测（GGPO 式，机制复用 M9）**：客户端 `RollbackSim` 跑全量 Sim——本地玩家零延迟预测、远端玩家沿用预测（M9 §5.3 策略原样）；服务器确认不逐帧下发远端输入，**和解统一走快照级**：`RollbackSim` 新增 `OnAuthoritativeSnapshot(frame, state, checksum)`——快照到 → 取本地环内同帧预测 checksum 比对 → 不符 → Restore 权威态 → 重放 frame+1..now（本地历史）→ 计数上报 `MismatchReport`。混合形态（远端走快照镜像）留调优，和解率不可接受时再议 | §5 章头"回退源=权威快照、重放范围=本地输入"；M9 零结构改动、全量复用；远端误差每 33ms 被快照覆盖 |
| 10 | **带宽预算锚点（首次实测前红线，实施记录校准）**：输入上行 ≤ 6 KB/s/客户端（16 B×60 + KCP/UDP 头 52 ≈ 4 KB/s 理论值）；快照下行 ≤ 32 KB/s/客户端（8 人满负荷全图 AOI、30Hz 增量，理论 ~18 KB/s + 冗余与头）；全量兜底帧不计常规预算（触发即计数观测） | §3.2 估算方法延续；"≤ 预算"验收需要预算先存在 |
| 11 | **E1 背压降级（M10 起带）**：per-client 发送队列上限 → 超限逐级降级（降快照率 → 收缩 AOI → 丢低优先级实体） | 《服务端架构》§10-E1：基线无背压，一个慢客户端会拖垮房间 |
| 12 | **E3 抗放大加固（M10 起带）**：连接 cookie（防 UDP 放大）+ per-IP 限速 + 重连**一次性票据** | 《服务端架构》§10-E3 |
| 13 | **AOI（MVP 验证等价性）**：网格过滤旋钮 `AoiCellSize/AoiRadius` 进 `SimConfig`，只影响广播、不影响判定与回滚重放；验收 = 开/关 AOI 结果一致 + 带宽差可观测 | §4.5-7；E2 优先级调度明确 **M10 之后**（不做） |
| 14 | **验收 harness = 全 .NET 无头对跑**：`RoomServer` 进程 + 2 个无头客户端进程（脚本输入 + `RoomClient` + `RollbackSim`）+ **网络损伤模拟器**（`LoopbackDamageSim`：延迟/丢包/乱序注入，测试 harness 专用，不进生产 `Transport/`）。Unity 侧本批只交付 `KcpNetworkService : INetworkService` 桥接（可编译），视觉装配留 M11 | 同运行时红线（M8 FMA 结论）；"同机两客户端对跑 5 分钟"用无头形态自动化 |

## 2. 分步实施（逐件施工图）

**批次划分**（四批，层叠推进）：

| 批 | 内容 | 目的 |
| --- | --- | --- |
| **第一批：LiteNet 骨架与协议** | 2.1 vendor（kcp2k/protobuf）+ asmdef/csproj/白名单 + 2.2 `.proto` 与生成 + 2.3 `Protocol/` 纯函数 + 2.4 `INetworkService` 契约 + `Transport/`（KcpPeer 收发/双通道/冗余） + 用例 | 传输与协议单源先冻结 |
| **第二批：RoomServer 权威循环** | 2.5 Acceptor/Session/Room（cookie/限速/buildHash）+ 2.6 FrameAggregator + AuthSim（缺席沿用）+ 输入两层校验 + E1 背压 + Ops 指标 + 用例 | 服务器能独立跑 60Hz 权威局 |
| **第三批：快照与回溯** | 2.7 SnapshotDiffer（增量/全量兜底/checksum/ackInput）+ AOI 网格过滤 + 2.8 服务器快照环 + 回溯判定（§3.4.1）+ ReconnectResp 能力 + 用例 | 广播与延迟补偿成形 |
| **第四批：客户端接缝与验收对跑** | 2.9 `RoomClient`（LiteNet）+ `RollbackSim.OnAuthoritativeSnapshot` 和解扩展 + `KcpNetworkService` 桥接（LiteGame）+ 2.10 损伤模拟器 + 无头双客户端 + §9 M10 验收全组 | 拿满里程碑验收 |

### 2.1 vendor 与工程骨架（~0 代码，纯装配）

`Assets/LiteNet/Vendor/{kcp2k, Google.Protobuf}`；`LiteNet.asmdef`（`noEngineReferences: true`）；`Assets/LiteNet/LiteNet.csproj`（双轨，`Directory.Build.props` 重定向 `.dotnet/`）；`RoomServer/RoomServer.csproj` + `Tests/LiteNet.Tests/LiteNet.Tests.csproj`；`.gitignore` 白名单三行；HybridCLR 排除清单登记 `LiteNet`。

### 2.2 协议定义与生成（`Proto/`，~120 行 .proto + 生成物）

消息面按 §4.5 协议矩阵；`Input(frameNo, wire[≤4 帧冗余], ackSnapshot, viewFrame)`；`StateSnapshot(frameNo, slotDeltas[] 或 fullState, checksum, ackInput, isFull)`。`scripts/gen-proto.ps1` 固定 protoc 版本；生成物入库。

### 2.3 `Protocol/`（~250 行）：打包解包纯函数

InputWire 打包（最近 4 帧冗余）、快照解包、信令序列化——零 IO 零状态零 kcp2k 依赖（决策 #4）。**用例**：往返序列化逐字节一致；冗余解包取最新有效帧；坏包丢弃不抛。

### 2.4 `Transport/` + 契约（~350 行）

kcp2k `KcpPeer` 收发、双通道分流、冗余发送、Session（心跳/超时）；`INetworkService`（§7.1 原文 ~30 行，接口在 `LiteFramework.Unity`，枚举 `NetState/NetChannel` 在 Core）。

### 2.5 RoomServer 会话与房间（~300 行）

Acceptor（握手→cookie→token/buildHash 校验→Session）、SessionManager（心跳/超时踢除/断线标记）、RoomManager + Room（成员表 playerId↔session）。E3 加固 + E1 队列上限骨架。

### 2.6 权威循环（~200 行）

`FrameAggregator`（`PeriodicTimer` 60Hz）：聚合（缺席沿用空输入）→ `SimStep.Step` → 服务端快照环 `Capture`（`LagCompHistory`）→ SnapshotDiffer → Broadcast。输入传输层校验（每帧≤1 条/玩家、ackSnapshot 单调且 ≤ 已广播帧号、非法帧号丢弃）。Ops 控制台指标（帧号/房间数/快照均长/丢包率/和解率汇总）。

### 2.7 SnapshotDiffer + AOI（~300 行）

上一广播帧副本对比 → 变化槽位 → 量化 zigzag；全量兜底（每 60 帧或 ack 落后）；AOI 网格过滤（旋钮）。**用例**：增量→全量往返一致；静止场景增量趋零；AOI 开/关判定结果一致。

### 2.8 回溯判定（~150 行）

开火输入带 `viewFrame` → 环回溯 → `ShootingSystem.Run` 单系统执行（历史态）→ 命令与帧事件**丢弃**（回溯只判命中，不结算当帧——结算在权威当前帧消费该判定）→ 恢复当前态。**用例**：150ms 模拟下"命中开火者所见位置"（§9 验收用例）；`LagCompHistory=0` 退化。

### 2.9 客户端接缝（~400 行）

`RoomClient`（连接/收发/冗余/ack 上报）；`RollbackSim.OnAuthoritativeSnapshot`（~120 行：环内同帧 checksum 比对 → 不符 → Restore 权威 → 重放本地历史 → `OnReconcile` 计数）；`MismatchReport` 上报；`KcpNetworkService : INetworkService`（LiteGame 桥接，本批只求编译通过）。**用例**：注入快照不一致 → 和解后与真值一致；快照超前（halt 态）→ 直接覆盖续跑。

### 2.10 损伤模拟与无头对跑（~250 行 harness + 验收组）

`LoopbackDamageSim`（延迟/丢包/乱序注入）；无头客户端（脚本输入 + RollbackSim）；验收组见 §3。

## 3. 测试与自测策略

| 组 | 用例 |
| --- | --- |
| **协议往返** | 打包→解包逐字节一致；4 帧冗余解包取最新；截断/坏包丢弃 |
| **权威循环** | 60Hz 定拍下输入聚合顺序确定；缺席沿用；迟到输入进下一帧 |
| **SnapshotDiffer** | 增量+全量重建 == 全量直拷；静止增量趋零；AOI 开/关一致；ackInput 正确 |
| **回溯判定** | 150ms 模拟延迟：命中"开火时刻目标位置"而非当前位置；深度 16 窗口外退化为当前帧判定 |
| **和解** | 快照与预测不符 → 重放后与后续快照收敛；halt 态快照超前覆盖续跑；`MismatchReport` 计数正确 |
| **E1 背压** | 队列超限 → 快照率降档 → AOI 收缩，房间其余客户端不受慢客户端拖累 |
| **E3 加固** | 无 cookie 握手拒答；超速丢包；重连票据一次性 |
| **对跑验收（§9 M10 行）** | 同机 2 无头客户端 + RoomServer 对跑 **5 分钟**：帧号稳定推进无累积落后、无死锁；**10% 丢包**不卡死（和解率上升但收敛）；人为注入不确定性（客户端篡改本地态）→ 快照覆盖兜底不发散；30Hz 带宽 ≤ §1-#10 预算（实测记录）；和解触发率全程可观测（Ops 输出） |
| **纪律** | 扫描器 0 违规（LiteNet 守 R5——禁裸 UNITY_EDITOR，双端编译红线；R1–R4 属 Sim 确定性纪律不适用；Vendor/ 第三方源码全局排除）；L1 全绿（207 + 新增） |

## 4. 完成判定（对账 §9 M10 验收）

- [ ] **同机两客户端对跑 5 分钟无卡顿累积**（无头 harness 自动化）

- [ ] **30Hz 快照下带宽 ≤ 预算**（§1-#10 锚点，实测记录进实施记录）
- [ ] **延迟补偿用例：高 ping（模拟 150ms）开火命中"客户端看到的那个目标位置"**
- [ ] 协议单源（`Protocol/` 零 kcp2k 依赖）+ `IRoomTransport` 窄端口就位（可替换性两刀）
- [ ] 输入两层校验（传输层挡非法 + Sim 内 clamp）+ buildHash 版本拒绝
- [ ] E1 背压降级 + E3 抗放大（M10 起带项）交付
- [ ] `LiteNet` 排除 HybridCLR 热更 + 启动期断言
- [ ] 纪律 0 违规；L1 全绿；RoomServer/无头客户端在 .NET 8 一键可跑（脚本留档）
- [ ] 行数对账（超 20% 写明原因）

## 7. 边界与风险

- **不越界**：不做 Unity 视觉装配（M11：`SimView`/插值接线/`PlayerController`/场景）、不做重连客户端流程与断线重进体验（M11，服务器能力已备）、不做 MatchMaker（MVP 固定房间号/好友码）、不做 E2 快照优先级（M10 后调优）、不做 Gate/Sim 拆分与 I/O 线程（触发条件未命中）、不做帧同步预案（判据未触发）
- **风险 1：和解率底噪**——M8 实测 Mono/.NET 1-ULP 差异意味着 Unity 客户端预测与 .NET 服务器**必然周期性和解**；无头验收（全 .NET）无此底噪，M11 demo 需重新观测并记基线。**对策**：和解率是质量指标非正确性前提（快照覆盖兜底）；预期写进 Ops 文档，勿在 M11 把底噪当 bug 排查
- **风险 2：kcp2k 版本漂移**——vendor 版本锁定并记录；升级按 vendor 目录整体替换 + 回归对跑
- **风险 3：protoc 工具链依赖**——生成物入库后运行期零依赖；生成脚本注明 protoc 版本，避免本机环境差异
- **风险 4：双轨 csproj 维护**——`RoomServer`/`LiteNet.Tests` 的 `Compile Include` 随新文件漂移。**对策**：按既有模式用通配 Include + 纪律测试钉死（缺文件即编译失败）
- **风险 5：`PeriodicTimer` 节拍漂移**——60Hz 长跑累积误差。**对策**：绝对时间锚定（nextTick = start + n×dt，不 tick+=interval）；对跑验收 5 分钟帧号线性度即检验
- **风险 6：回溯判定与当前帧结算的双路径**——回溯只出命中结论，结算必须回到当前帧，两路径不一致会产生"幽灵命中/漏判"。**对策**：回溯产物只进当前帧的命令缓冲，用例钉死（150ms 用例 + 0ms 等价用例）
- **风险 7：协议单源红线回潮**——任何"服务器侧另写一个消息结构"的诱惑即违规。**对策**：RoomServer csproj 直接 Compile Include `LiteNet/Protocol`，物理上双写不可能
