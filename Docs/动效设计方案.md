# 动效设计方案

> 制订日期：2026-09-13。定位：**表现层运动设计的统一规范**——动效分类与归属、技术选型纪律、框架接法（谁触发/谁承载）、性能红线与里程碑挂接。
> 前置：《自研框架设计方案》§1.3（转场策略归属）/§4.7（命令式控件类型）、《M4实施指导》§2.2/§2.4（ITransitionStrategy / 受控 API）、《M5 纵向切片》红线（表现与判定分离）、《状态同步实施方案》§6.2（动效不回滚）。
> 一句话定位：**动效是判定的可见投影，不是判定的组成部分——它可以在任何时刻被打断、跳过、重播，而游戏事实（血量/经济/命中）毫发无损。**

---

## 0. 四条原则（不可让步）

1. **动效永不携带判定**——表现与判定分离（M5 红线提前生效于此）：DOTween / Animator / 粒子只写 Transform / 组件表现，禁止回写任何逻辑状态；"动效播完"不是任何逻辑事件的触发条件。
2. **时钟分轨**：UI 动效挂 `IUIClock`（时停不停转场），世界动效挂 `IWorldClock`（时停冻结）——动效实现不自读 `Time`（M4 §1e 决策的推论）。
3. **热更边界**：动效**实现资产**（Animator Controller / 粒子 prefab / 材质）随 YooAsset 增量下发（M6 闭环）；动效**触发与编排**进 Lua（经受控 API / 序列执行器）或 Luban 表（时长 / 曲线 / 目标控件名可热更调参）——**动效的 C# 实现代码出包**。
4. **每帧动效白名单**：持续运行的动效（呼吸 / 脉冲 / 待机飘动）必须 `SetLoops` 复用单 tween + 纳入数量预算；一次性动效（弹窗 / 飘字）低频不限。禁止"每帧 new 一个 tween"的写法。

## 1. 分类与归属（五类动效，各归各家）

| 类 | 内容 | 技术 | 归属 / 触发 | 驱动时钟 |
| --- | --- | --- | --- | --- |
| **UI 转场** | 界面打开/关闭/切换的位移、缩放、淡入出 | DOTween（壳内通用转场组件） | `ITransitionStrategy`（M4a 策略三件之一）——Lua 可经 Strategies 注册表换风格 | UIClock |
| **界面内反馈** | 按钮按压、数值滚动（CountUp）、飘字、红点脉冲、引导高亮 | DOTween + 受控 API 动效口（§3） | Lua 经绑定面受控 API 触发（§4.7 命令式——动效本就是命令式控件类型） | UIClock |
| **角色动画** | 移动/攻击/受击 state machine | Animator Controller，**参数单向驱动**：C# 玩法系统（联机 = SimView 观察状态）写参数；Animator 事件只触发表现（脚印/音效），绝不回写逻辑 | 玩法系统 / View 镜像层 | WorldClock |
| **特效** | 命中、技能、拾取 | 粒子（Shuriken）+ DOTween 组合 | 联机：FrameEventBuffer 观察 + `silenceUntilFrame` 防重播（状态同步 §6.1/6.2 已定）；单机：事件桥 | WorldClock |
| **相机动效** | 震屏、推拉、聚焦 | Cinemachine Impulse + DOTween | 事件桥 / 序列执行器 | WorldClock |

## 2. 技术选型纪律（DOTween 为全项目唯一 tween 库）

- **唯一性**：DOTween 已 vendor（Plugins/Demigiant）；禁再引入 iTween / LeanTween / Prime31 等第二 tween 库；禁 DOTween Pro（非必须的外部资产）。
- **防泄漏（§7.3 内存红线同款）**：所有 tween **`SetLink(target.gameObject)`**——目标销毁自动杀；`SetAutoKill(true)` 为默认；循环 tween 显式保存句柄可杀；界面进入 Recycled 态时壳统一 Kill 该界面全部关联 tween。
- **防 GC**：高频件（飘字 / 数值滚动）用对象池 + tween 复用（`SetTarget` 定向 Kill 后重用）；规格在 M5 Profiler 作业实测后定（记入实施记录）。
- **Animator 纪律**：Controller 资产随 YooAsset 热更；运行期**参数驱动单向**（Set/SetFloat/Trigger），Animator 状态机不反向调用业务方法。
- **联机补充**：动效不进回滚、不参与确定性（Sim 层禁 Animator/Transform——状态同步 §0 红线 1）；本地预测表现 0 延迟（开火反馈），命中特效等权威确认（§6.2 已定，此处归拢）。

## 3. 框架接法（谁触发、谁承载）

1. **转场动效** = `ITransitionStrategy` 实现内容（M4a 交付默认实现：淡入淡出 + 位移灰盒版）——壳在七态切换点调用，策略自行编排 tween。
2. **界面内动效口** = 绑定面受控 API 的最小扩展（M4a 定集）：`Pulse / Flash / Slide` 三件起步（**YAGNI——不预作完整动效词汇表**，需求来了按此模式加）；Lua 经 `OnButton` + 动效口组合覆盖绝大多数界面反馈。
3. **演出级动效**（技能时间轴 / 剧情演出）= **时序执行器**编排（M4b 交付、M5 消费）：动作序列数据进 Luban 表可热更调参；DOTween 挂在执行器步骤的**表现位**，与判定的推进互不等待——执行器冻，动效可继续播完但不产生事实。
4. **Lua 不直持 DOTween API**：桥面最小纪律——一切动效经受控 API / 策略 / 执行器三口进。

## 4. 性能红线（移动端）

- **Canvas 拆分**：每界面独立 Canvas；**动效中的元素再拆子 Canvas**（防整页 rebatch）——写入 M4a prefab 规范。
- **overdraw 预算**：全屏 UI 动效叠加 ≤ 2 层；全屏转场用单全屏 Image 淡入出，禁多层渐变叠。
- **目标**：动效播放不掉帧（Profiler 实测记档，M5 作业）；低端机降级 = 策略换短时长/直切，不是砍功能。
- **泄漏即红线**：界面关了 tween 还在跑 = bug；DevHUD 后续可加"活跃 tween 计数"位（挂在 UI 壳 IModuleStats）。
